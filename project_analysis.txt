# GigSurance - Project Analysis

## 1. Project Motive
GigSurance is a parametric micro-insurance platform designed specifically to protect the livelihoods of gig workers. Gig workers often lose out on daily income due to uncontrollable external factors such as extreme weather conditions or civil disturbances. The motive of this project is to provide a safety net by automatically triggering financial payouts when these adverse conditions occur, compensating them for the lost working hours without requiring a manual claims process.

## 2. Core Working & Architecture
The project is built with a modern, scalable architecture separated into a frontend and a backend:
- **Frontend**: A Single Page Application (SPA) built using React, Vite, TypeScript, and Tailwind CSS. It uses `shadcn/ui` for components, `framer-motion` for animations, and `@tanstack/react-query` for data fetching.
- **Backend**: A fast, asynchronous API built with FastAPI (Python) and backed by a MongoDB database (using `motor` for async database operations).
- **Automation**: An asynchronous scheduler (`APScheduler`) runs background jobs to constantly monitor external conditions.
- **Integrations**: 
  - **OpenWeather API** for real-time weather monitoring.
  - **NewsAPI** for detecting civil disturbances.
  - **Razorpay** for handling premium payments.

## 3. Key Functionality & Flows

### A. User Onboarding & Policy Management
- **Registration**: Users create an account and specify their working location (city) and daily working hours.
- **Policy Subscription**: Users subscribe to an insurance policy that has a defined "weekly cap" for payouts. 
- **Premiums**: Users pay premiums to keep their policy active, handled via Razorpay integration (`/api/payments/create-order` and `/api/payments/verify`). A weekly background job manages premium updates.

### B. The Trigger Engine (Parametric Insurance Core)
- The backend runs a `trigger_check` background job every 10 minutes.
- **Weather Triggers**: Fetches real-time weather for the user's city using OpenWeatherMap. If the temperature exceeds a threshold (e.g., > 45.0°C) or rainfall is excessive (e.g., > 12.0 mm/hr), a trigger is logged.
- **Civil Triggers**: Fetches local news via NewsAPI looking for keywords like "bandh", "curfew", "strike", "protest", or "riot". If a match is found, a civil disturbance trigger is logged.

### C. Automated Payouts
- When a trigger becomes active in a specific city, the system identifies all onboarded users in that city with an active policy.
- **Fraud Check**: Ensures the user's registered city matches the trigger city.
- **Calculation**: The system calculates the user's remaining working hours for the day (based on current time and their defined shift). It computes a proportional payout based on their weekly cap and remaining hours.
- **Crediting**: If the payout is valid and the user hasn't already been paid for this specific trigger, the amount is recorded in the `payouts_collection`.
- **Notifications**: Users receive automated notifications that their payout has been credited due to the specific trigger (e.g., "₹500 credited due to heat in Mumbai").

## 4. Main Features
- **Real-time Monitoring Dashboard**: Users can view live triggers, weather conditions, and risk levels for their zone on the "Monitor" page.
- **Zero-Claim Processing**: Payouts are entirely parametric and automatic. Users don't need to file claims or submit proofs.
- **Granular Payout Calculation**: Payouts are dynamically calculated based on the exact hours lost during the worker's specific shift, rather than a flat daily rate.
- **Payment Gateway Integration**: Secure integration with Razorpay for handling financial transactions.
- **Admin Panel**: To oversee platform health, user policies, active triggers, and financial metrics.
- **History & Analytics**: Users can track their past payouts, premium payments, and overall coverage analytics.
